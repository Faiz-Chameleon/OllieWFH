# Recurring supplements (same day, later session)

Branch `feature/recurring-supplements` in **both** repos. **Not committed, not pushed, migration not applied anywhere.** Author: Faiz-Chameleon (with Claude). Production touched: no.

## What it does
A supplement now repeats **every day**, on **specific weekdays**, or **every N days** (1–365, counted from the start date). It can have **up to 6 dose times a day**, a start date and an optional end date. Reminders are calculated in the **user's timezone**. Before this, the server used its own clock, so 09:00 meant 09:00 on the VPS.

## Backend (`ollie_backend`), status: done locally, verified with mocks
- **Schema / migration** `prisma/migrations/20261005150000_add_supplement_recurrence`. **Additive only**: it adds 7 nullable or defaulted columns to `UserSupplement` (`frequency` enum default `DAILY`, `reminderTimes` JSON, `daysOfWeek` JSON, `intervalDays`, `startDate`, `endDate`, `timeZone`). There are no drops and no data rewrites. The SQL was generated offline with `prisma migrate diff` (schema to schema, no database connection).
- `utils/supplementReminder.js`: recurrence engine (`normalizeSchedule`, `scheduleFromRecord`, `getNextOccurrence`). It uses calendar-day arithmetic plus `utils/timezone.js`, so it doesn't depend on the server's timezone.
- `controllers/user/userSupplementController.js`: create and update accept the new fields. Update merges them with the stored schedule. Timezone priority: request `timeZone`, then `User.timeZone`, then UTC.
- `schema/user/supplement.js`: Joi rules for the new fields.
- `jobs/supplementReminderScheduler.js`: advances each supplement to its next scheduled dose. It no longer adds a fixed 24 hours.
- **Backward compatible.** Older app builds that send only `reminderTime` get a DAILY schedule. Existing rows behave as before; they are read as DAILY at `reminderTime`, falling back to the user's timezone and then UTC. Responses still include `reminderTime`, set to the first time.
- Verification:
  - 22 engine tests, run with `TZ=America/Los_Angeles`. They cover DST, Auckland date rollover, weekly, interval, end dates and validation.
  - 17 controller, Joi and scheduler tests with Prisma stubbed.
  - Every Prisma call type-checked with `tsc --strict` against the generated client.
  - **Not** run against a real database.

## App (`OllieWFH`), status: done locally, `flutter analyze` clean, 24/24 tests pass
- `lib/Models/supplement_model.dart`: new fields plus schedule logic (`isScheduledOn`, `doseKeysOn`, `upcomingDoses`, `scheduleSummary`, `toJson`).
- `lib/home/Supplements/supplement_alarm_plan.dart` (new) plans local alarms:
  - Daily and weekly schedules use OS-repeating alarms, so they keep firing even if the app isn't opened.
  - Every-N-days schedules, schedules with an end date or future start, and doses already taken today use up to 12 one-shot alarms that are topped up on every sync.
  - Each supplement owns 64 notification ids (base `1,000,000`). The old single id (`700000+`) is still cancelled.
- `lib/services/firebase_service.dart`: "taken" is now tracked **per dose**, stored as `{date, times[]}`. The old date-only value is still read. The notification "Taken" action marks that specific dose and re-plans the supplement's alarms in the background isolate.
- `supplement_controller.dart` / `supplements_screen.dart`:
  - The card shows the schedule, the next reminder, and "Take 1/2" / "Taken" / "Not today".
  - The sheet adds frequency chips, weekday chips, an every-N-days stepper, start and end dates, and multiple time chips.
  - Smoke-tested in widget tests at 320 and 414 px widths. Two overflows were fixed in the process.

## Rollout, read before merging
1. **The migration must reach the production database before, or together with, the backend deploy.** Prisma selects every column. If the code goes live without the columns, every supplement endpoint fails and the reminder scheduler switches itself off ("schema mismatch").
   - The deploy workflow runs `prisma migrate deploy`, but it is set to **skip on failure** ("baseline/non-empty DB"). A green deploy does not prove the migration applied. Check the deploy log or the table afterwards.
   - This is a production schema change. Under the org rules it needs two explicit confirmations.
2. Deploy the backend before shipping the app. The new app sends fields the old backend's Joi schema rejects.
3. Older app builds still installed will schedule a **daily** local alarm, even for weekly or interval supplements. The server push is correct. This resolves once users update.

## Known limits, not changed
- iOS allows 64 pending local notifications per app. A weekly schedule with many times and days uses up to times × days slots, so very heavy schedules can exceed it on iOS.
- "Taken" state is stored only on the device, as before. The server still sends its push for a dose taken early.
- `verifyUserToken` doesn't load `timeZone`, so `req.user.timeZone` is always undefined. Supplements look it up directly. The **task** endpoints (`userTaskController.js`) still fall back to UTC because of this. It was left alone because `middleware/auth.js` is part of the uncommitted Care Circle diff.

# Recurring, detailed to-dos + home widget (same day, third block)

Same branch `feature/recurring-supplements` in both repos. **Not committed, not pushed, migration not applied anywhere.** Production touched: no.

## What it does
- Tasks can repeat **daily, on chosen weekdays, every N days, or monthly** (same day of month; the 31st falls back to the last day of shorter months), with an optional end date.
- Each day of a recurring task is completed separately, and can be removed from that one day without deleting the series.
- New per-task details:
  - priority (Low/Medium/High)
  - category
  - a **checklist** of up to 30 steps, tracked per day for recurring tasks
  - notes
  - **reminder lead time** (at the time, 5/15/30/60 minutes or 1 day before), or no reminder
- Completing a task can now be **undone**.
- The home **Daily Tasks** card always shows **today**. It has a progress bar, the next three tasks (not-done ones first) with one-tap ticking, "+N more", an add button, and a retry option when loading fails.

## Bugs fixed on the way
- `rescheduleTask` with a new date or time always crashed: it called `buildScheduledDateTime`, which doesn't exist. The app's "edit task" date changes therefore never saved.
- Users west of UTC didn't see tasks on their day. The date was stored as UTC midnight but searched as a local-day range. The date is now stored as a local `taskDate`; older rows fall back to `scheduledDate`'s UTC date.
- `getTaskByDate` returned at most 10 tasks and the app never paged. The default is now 100, and the app asks for 100.
- The home card showed whichever date the To-Do screen last viewed, not today.
- The bot screens (`ollie_chat_screen`, `conversational_chat_screen`) opened `TodoListScreen`, a fake to-do list with local sample data. They now open the real screen.
- An `Obx` misuse in the new header and filter (caught by the widget tests) and narrow-screen overflows were fixed.

## Backend (`ollie_backend`), status: done locally, verified with mocks
- **Migration** `prisma/migrations/20261005170000_add_task_recurrence_and_details`. **Additive only**: 10 new `Task` columns, all nullable or defaulted, so existing tasks stay non-recurring, MEDIUM priority, with the same 5-minute reminder. It also adds a new `TaskOccurrence` table (per-day completed, skipped and checked items; cascades with its task) and two indexes. There are no drops and no data rewrites.
- `utils/recurrence.js` (new): calendar helpers now shared by supplements and tasks. Supplements were refactored onto it, and all their tests still pass.
- `utils/taskSchedule.js` (new): validation, occurrence expansion, next-reminder calculation and the response shape.
- `controllers/user/userTaskController.js`: rewritten around the engine. **Routes and response shapes are kept**: by-date still returns `data: [[...]]`, `markAsCompletedTask` with an empty body still completes, and `rescheduleTask` remains the edit route. New request fields are optional.
  - New `PUT /user/task/toggleChecklistItem/:taskId`
  - New `GET /user/task/getTaskSummary?from&to` (per-day counts, at most 62 days, used for calendar dots)
  - `DELETE` accepts `?scope=occurrence&date=` to remove one day
- `jobs/taskReminderScheduler.js`: recurring tasks advance to the next day that isn't done after each send. A day ticked off early gets no reminder. The message reflects the lead time.
- Verification:
  - 21 engine tests: weekly, monthly end-of-month, interval, DST and timezone, a 1-day lead, legacy rows, validation.
  - 19 endpoint and scheduler tests against an in-memory Prisma fake, run with the server in both US and Pakistan time.

- **Symptom reported:** after creating a task, the home Daily Tasks card didn't update.

The user pushed it after two confirmations. Deploy run 37351882641 succeeded: no migrations, health check passed at 17:54:57 UTC.

# Games: Tic Tac Toe board scrolled off screen (local, not shipped)

- **Symptom:** on the Games screen, swiping the game pushed the whole board up and left empty space.
- **Cause:** the Tic Tac Toe board (`lib/CareCircle/assistance/your_post_screen.dart`, opened by the "Tic Tac Toe" tile) was a scrollable `GridView`. Its cells were sized from the screen width with 30px padding, so on shorter phones the bottom row was cut off and the board scrolled. On every phone, Android's stretch overscroll and iOS's bounce moved it while swiping. Pac-Man, Tetris and 2048 don't scroll and weren't affected.
- **Fix:** the board is now the largest square that fits the space left (`Center` > `AspectRatio(1)`) with `NeverScrollableScrollPhysics`.
- **Test:** `test/tic_tac_toe_layout_test.dart` covers 4 phone sizes on both Android and iOS. It checks that all 9 cells are on screen and that the board doesn't move during or after a swipe. It fails on the old code and passes now (stable over 5 runs). Full app suite: 51/51.
- **Ships with** the next app build. No backend change.
